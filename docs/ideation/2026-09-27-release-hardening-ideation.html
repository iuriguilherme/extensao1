Grounding Context

Codebase Context

  • Stack. Phaser 4 + TypeScript + Vite, Vitest (30 tests). Content in src/data (11 lessons in 3 tracks, 21 parts in 7 slots, 10 handcrafted nodes with literal x/y), rules in src/core, nine scenes.
  • One machine. computeSpecs(installed) derives cpuPower = cores × GHz, RAM, storage and linkMbps = min(nic, router) from a single build. One nic slot and one router slot. roundSeconds caps at 30 s (CPU power 88) and mistakesAllowed caps at 64 GB.
  • Breached nodes are bare ids. GameState.breached: string[] holds no per-node resources; breach() pays node.reward once and 20% on replays.
  • No clock. Nothing ticks outside the mini-game timer; the save is a synchronous snapshot with no timestamp.
  • Closed difficulty. Difficulty = 1 | 2 | 3, bits = [4, 6, 8], roundCount = [5, 7, 9]; the only side job is hardcoded binary difficulty 1 for $25. Rounds use createRng(Date.now()).
  • Teaching loop. Lessons gate parts, setup and nodes; every mistake shows an explain; hardware and IP errors are teaching sentences; content-integrity tests guard the data.
  • Text. About 145 English user-facing strings spread across data, scenes and core messages; patterns like "mistake(s)", $${money}, padEnd alignment; tests assert English regexes; index.html has lang="en".

External context

  • Bitburner: Hacknet nodes as passive producers and BitNode prestige as "finish, then continue under new rules".
  • Grey Hack: procedurally generated networks as the content engine. Cisco Binary Game: a single fast bit drill reused over a million times.
  • Bitcoin difficulty retargeting keeps block rate stable as hash power grows.
  • BNCC Computação research exists in Brazil, but no PT-BR "hack the network to learn IT" game was found.
  • Serious-games ethics literature warns hacking and crypto games can normalize harm and recommends sanctioned-lab framing.

1. Swarm nodes are real machines behind switch ports

Description
Give every node an installed build made from the existing parts catalog and evaluate it with the same computeSpecs(). The NOC becomes a small rack where routers and switches have a port count; each held node uses one port, so the node cap is the total port count. Nodes behind a switch share its uplink, so usable swarm power is limited by an oversubscription ratio (for example 4:1). "Specialized network hardware" is then literally a switch or router part inside a node's build: holding that node adds its ports and uplink. Split what resources do: the player's own rig keeps driving intrusion time and mistakes, while the swarm pool drives node requirements, mining and a post-ending tier the Core alone cannot unlock. GameState separates held from ever breached, with a save migration for saves that already hold all ten nodes.
Basis
direct: breached: string[] (state.ts) carries no resources; linkMbps: nic && router ? Math.min(...) (hardware.ts:97) is already a derived bottleneck; lessons.ts quiz explain "A link runs at the speed of its slowest end."; roundSeconds caps at 30 s and mistakesAllowed at 64 GB (hardware.ts:112-121), so pouring swarm power into intrusions saturates fast; the Core's requirements are reachable by one top rig. external: leaf/spine oversubscription in data centers; BOINC shared-capacity model.
Rationale
One data model covers three parts of change #3: contribution (nodes have builds), the cap (ports), and specialized hardware raising the cap (a switch part in a node). It also turns the cap into real networking content instead of an arbitrary number, and gives mining a resource pool that is not the same number as the intrusion timer.
Downsides
Largest refactor of the set: the single nic/router slot becomes a rack, node data grows, and the Workbench needs a NOC view. Save migration needs a rule (for example, keep the strongest nodes up to the new cap).

2. Mining runs on an action clock and replaces breach cash

Description
Retire the cash branch of breach(): breaching a node only adds it to the swarm (and replays pay nothing). Income comes from mining. Time advances in blocks driven by player actions (finishing a lesson, an intrusion, an install, or an explicit "minerar N blocos" button) instead of a wall clock, so the economy is deterministic, testable, and has no offline-idle exploit. Each node splits its CPU between mining and an intrusion reserve; nodes are dispatched in merit order (best hash per watt first), and each block pays in proportion to the CPU assigned to mining.
Basis
direct: no tick exists outside MinigameScene.update and GameState has no timestamp (evidence-mining-economy.md); breach() in state.ts pays node.reward and REPLAY_RATIO 20%; earn/breach fire once in MinigameScene.finish; roundSeconds(cpuPower) already converts CPU to gameplay. external: Crypto Mining Simulator's allocation lever; power-grid merit-order dispatch.
Rationale
Change #4 says mining must replace hack-for-cash and must consume CPU. Without an explicit clock decision, "consume" means nothing; with a block clock, both requirements become one small, pure function that tests can drive.
Downsides
Block time feels less like an idle game than real time; some players expect income while away. Balancing needs a spreadsheet pass because lessons stay the only other income. Variants worth deciding in brainstorming: an electricity bill (ANEEL tariff flags) as a money sink, and solo versus pool mining.

3. PT-BR as a style system, not a translation pass

Description
Write Portuguese directly in the data and scenes (no i18n layer, since there is no second language), but back it with three small pieces. A termos.ts glossary decides which technical terms are translated ("roteador", "máscara de sub-rede", "placa de rede") and which stay in English as Brazilian IT uses them (DNS, firewall, hash, switch). A fmt.ts on Intl pt-BR formats prose numbers with a decimal comma ("4,8 GHz", "R$ 1.200") while technical notation (IPs, masks, CIDR) never localizes, provides real plurals instead of "erro(s)", and uses a part-gender field for agreement ("Placa-mãe instalada", "Processador instalado"). Tests assert on issue codes (psu-overload, ip-broadcast) instead of wording, plus one test that scans user-facing strings for leftover English words.
Basis
direct: about 145 English strings (evidence-pt-br.md); "mistake(s)" at HubScene.ts:38 and MinigameScene.ts:54; tests assert /socket/, /DDR5/, /Smart TV/, /BROADCAST/, /not your router/; index.html lang="en"; round1() yields "4.8". external: Microsoft Language Portal PT-BR terminology conventions.
Rationale
Translation alone would leave "4.8" instead of "4,8", broken gender agreement in toasts, inconsistent terms across 11 lessons, and a test suite that breaks on every wording change. These pieces make PT-BR a rule that every new string (swarm, mining, cities) follows automatically.
Downsides
Needs a native-speaker pass on the glossary and lesson text; the English-word scan needs an allow-list for kept terms. Longer Portuguese strings will need layout checks on fixed-width buttons.

4. New systems ship ethical and lesson-gated

Description
Frame every city as an authorized lab or pentest contract ("contrato de laboratório autorizado"), and name the real-world equivalent honestly: using other people's machines to mine is cryptojacking and a crime. Add optional lectures on Lei 12.737/2012 (Lei Carolina Dieckmann), proof-of-work and its energy cost, and switch ports and oversubscription. Mining and the NOC rack unlock through the same lesson → quiz → explain gate as every existing part, and every new stat (hash rate, ports in use, oversubscription) gets a MISSING_HINT-style explanation, covered by the content-integrity tests.
Basis
direct: no existing explain string covers mining or proof-of-work; MISSING_HINT (hardware.ts:26-34) and the lesson requires graph plus "every referenced lesson exists" test. external: DiGRA serious-games ethics and ethical-hacking education literature; Lei 12.737/2012.
Rationale
For a university extension project, a game that rewards mining on breached machines without comment is a reputational risk. Using the existing gate keeps the new systems as teachable as the old ones at almost no engineering cost.
Downsides
More text to write and review (in Portuguese). The framing must stay light enough not to feel like a lecture inside the game.

5. One open-ended difficulty dial for side jobs and mining

Description
Replace Difficulty = 1 | 2 | 3 with a numeric level that generators read through formulas: bits grow 4 → 6 → 8 → … → 16, subnet prefixes and CNAME chains get harder, rounds grow, each capped at a teaching ceiling. Side jobs become a job board of tiers on that dial, weighted toward the area where the player misses most (spaced review), with tiers unlocked by accuracy rather than cash. The same dial drives proof-of-work: "mine a block" is a hash/bit round whose required leading zero bits retarget upward as the swarm grows, so income grows more slowly than the swarm and endless play does not break the economy.
Basis
direct: export type Difficulty = 1 | 2 | 3; (minigames.ts:33), const bits = [4, 6, 8][d - 1]; (:76), roundCount [5, 7, 9]; the only side job is hardcoded binary level 1 for $25 (HubScene.ts:74-76). external: Bitcoin's difficulty retarget every 2016 blocks; Cisco Binary Game's ramping drill.
Rationale
The user's own example ("8 bits or more") needs a level outside the current union. One dial serves side-job tiers, harder cities and mining balance, instead of three scaling systems.
Downsides
Touches every generator and the exhaustive generator test. Teaching ceilings are a pedagogy decision the team must make (for example, is a /30 subnet question at level 12 still useful?).

6. Seeded cities that are real IP plans

Description
Keep the handcrafted city as the finite campaign and generate extra cities from a seed. Each generated city is a real address plan: for example a /16 split into subnets, node IPs valid inside their subnet, gateways that make sense, all checked by ip.ts so the map itself is correct networking. City types (NAT, VLAN, IPv6, VPN) unlock through optional lectures via the existing requires field. Seeds are shareable as a class code ("código da turma", e.g. RIO-4821), replacing createRng(Date.now()) where needed, so a whole class plays the same city and rounds with no server.
Basis
direct: ten nodes with literal x/y in nodes.ts; buildRounds(id, d, rng) is already seeded; createRng(Date.now()) at MinigameScene.ts:50; NetNode, nodeStatus and checkRequirements are generic. external: Grey Hack procedural networks; roguelike daily seeds.
Rationale
"More cities" becomes more networking practice, not just more map. Class codes make procedural content usable by a teacher, which matters for the extension project.
Downsides
Graph layout on 1280×720 without overlaps is real work. Validating generated plans needs property tests over many seeds.

7. The ending becomes a formatura, then pós-graduação

Description
Breaching the Data Center Core stays the ending, presented as a graduation: a "Certificado de conclusão" screen listing lessons completed and accuracy per area. After it, optional tiers (Especialização, Mestrado, Doutorado) raise the difficulty dial, open procedural cities and add optional lectures, each with its own certificate. Combined with a class code, the certificate gives the extension project per-student evidence of learning.
Basis
direct: the win text in objective() ("certified root", state.ts:90) and phaseOf() === 'won' change nothing else today; store.ts merge-defaults can add a tier field to old saves. external: Bitburner BitNodes (continue after the ending under new rules; unlike Bitburner, this keeps progress).
Rationale
Satisfies "there must be an end" and "keep going" with one clear structure that Brazilian students recognize, and produces something teachers can use.
Downsides
Accuracy tracking needs new state. The academic ladder is a theme choice the team may prefer to name differently.
